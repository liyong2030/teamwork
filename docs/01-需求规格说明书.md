| 文档属性 | 内容 |

| 文档名称 | 需求规格说明书 |
| 版本 | V1.0（MVP） |
| 适用范围 | 团队内部周报提交统计、项目任务管理 |

## 1. 建设目标

### 1.1 业务痛点

1. **周报靠人工催、人工统**：谁是组员谁是组长，谁交了谁没交，靠 Excel 和群接龙，口径一周一变。
2. **周报与任务两张皮**：任务在系统 A 里更新，周报在系统 B 里手写，两边数据对不上，管理者看到的周报是加工过的信息而非事实切片。
3. **历史数据不可追溯**：补交后历史统计被"洗白"，无法真实反映团队执行情况。

### 1.2 产品定位

> **让周报成为任务数据的时间切片视图，而不是一次额外的文字作业。**

一句话核心流程：成员平时更新任务 → 周五点「生成周报草稿」→ 系统自动汇总 → 人补两句话 → 提交 → 组长看统计看板。

### 1.3 MVP 范围界定

| 纳入 | 明确不做（二期评估） |
|---|---|
| 组织与用户管理、部门/组、三种角色 | 即时通讯、文件网盘 |
| 项目与任务两级 CRUD、看板、清单 | 子任务层级、甘特图、依赖线 |
| 任务状态机 + 变更流水 | 工时计费、OKR、绩效考核 |
| 周报自动生成草稿、提交、修订留痕 | 移动端原生 App（本期响应式 Web） |
| 提交/迟到/补交/未交统计与趋势看板 | LDAP/AD、企业微信扫码登录（预留接口） |
| 请假豁免、站内+邮件提醒、审计日志 | 工作流引擎、自定义表单 |

## 3. 组织域需求

### FR-ORG-01 部门管理
- 支持部门/小组两级以内层级（`parent_id` 自引用，本期多级仅做展示不做递归统计）。
- 部门停用后，其成员不再计入应提交名单。
- 每个部门可设置多名组长（`is_leader`）。

### FR-ORG-02 用户管理
- 字段：登录名、姓名、邮箱、所属部门（可多）、是否在职、是否管理员、**认证来源**。
- **禁止物理删除用户**，离职仅置 `is_active = false` 并保留全部历史数据。
- 支持管理员重置密码，重置后强制改密（统一身份认证账号无本地口令，需先解绑）。

### FR-ORG-04 统一身份认证（SSO）

**模式：后端代理校验**。登录页照旧提交账号 + 口令，由后端把这对凭据提交给 IdP 校验，
通过即签发本系统 JWT。**只做认证，不同步组织架构**——部门归属、组长身份、角色一律保持本地管理。

| 项 | 说明 |
|---|---|
| 支持协议 | CAS（REST 换 TGT→ST→校验）、OIDC（password grant + userinfo）、LDAP/AD（simple bind） |
| 未支持 | SAML 2.0 需浏览器跳转（SP-initiated），与本模式不兼容，二期实现 |
| 会话 | 认证通过后签发与本地登录完全相同的 JWT，权限模型不变 |

**账号解析规则**（IdP 校验通过后）：

| 优先级 | 条件 | 行为 |
|:--:|---|---|
| 1 | 存在 `(auth_source, external_id)` 匹配的账号 | 直接登录，仅补全空的姓名/邮箱 |
| 2 | 存在同名的**本地**账号且开启 `AUTH_SSO_BIND_EXISTING` | 绑定为 SSO 账号：清除本地口令，保留部门/组长身份 |
| 3 | 无匹配且开启 `AUTH_SSO_AUTO_CREATE` | 自动建号：普通成员、无本地口令、落入「未分组」部门 |
| — | 以上都不满足 | 拒绝登录并提示联系管理员 |

**三条安全底线**：
1. **超级管理员账号不会被自动绑定**——它是 IdP 故障时的本地应急通道，只能由管理员手动绑定；
2. **SSO 账号禁用本地口令登录**（本地入口返回 `sso_required`，前端自动改走 IdP），
   否则等于给 IdP 之外的弱口令留了后门；
3. **IdP 不可达必须报 503（`sso_unavailable`）**，绝不能混同为"用户名或密码错误"，
   否则 IdP 故障时运维无从判断。

**管理员操作**：手动绑定（`POST /users/{id}/sso-bind`）、解绑（`POST /users/{id}/sso-unbind`，
生成随机初始口令并强制改密）、连通性自检（`GET /system/sso/status`，不返回任何密钥）。

**配置入口**：协议与端点参数全部来自服务端环境变量（`AUTH_SSO_*`、`CAS_*`、`OIDC_*`、`LDAP_*`），
修改 `server/.env` 后重启后端生效。**系统设置**页提供只读的「统一身份认证」卡片：展示当前协议、
开关状态、脱敏后的端点参数（含对应环境变量名）与一键连通性自检，用于运维不下服务器排障。

### FR-ORG-03 请假与豁免
- 成员提交请假（起止日期 + 事由），组长审批。
- **审批权限**：管理员可批任何人（含自己，避免单人部署无人可批）；部门组长可批**本部门成员**，
  **不能批自己的**（自批自销会破坏豁免口径，其上级是管理员）；普通成员无审批权。
- 审批动作含通过 / 驳回，驳回**必须填写原因**；每次审批写审计日志（审批人、时间、结论、意见）。
- 页面按三个分区呈现：待我审批（待办，置顶且带数量角标）/ 我的请假申请 / 团队请假记录（只读）。
- **仅 `approved` 状态的请假参与豁免判定**。
- 豁免判定：请假区间与本周任意一天相交，即本周不计入应提交名单。
- 已审批通过的请假不能由本人撤回，需联系组长/管理员作废。

## 4. 项目任务管理需求

### FR-TASK-01 结构
- 两级：**项目 → 任务**。不做子任务，改用任务内「检查清单」（可勾选条目）替代。
- 项目字段：名称、编号、归属部门、负责人、状态（`planning/active/paused/archived`）、周期。
- **项目编号自动生成且唯一**：格式为 `PRJ-{年份}-{三位序号}`（如 `PRJ-2026-001`），序号按自然年递增；新建时可留空由系统生成，也可手工填写但必须唯一（数据库层另有唯一约束兜底）。
- 任务字段：标题、所属项目、负责人、协作人（多个）、优先级（P0–P3）、开始/截止日、进度百分比、预估工时、实际工时（选填）、标签、描述。

### FR-TASK-02 五态状态机

```
TODO（待办） ──► IN_PROGRESS（进行中） ──► DONE（已完成）
     │                   ▲   │
     │                   │   └──► BLOCKED（已阻塞）──► （解除后回到 IN_PROGRESS）
     │                   └───────────┘
     └──────────────────► CANCELLED（已取消）
```

规则：
1. 可变更状态的人：负责人、协作人、所属部门组长、管理员。
2. **`DONE` 不需要审批**——引入审批会让周报自动草稿出现"待确认"脏数据。
3. **每次状态或进度变更必须写 `task_status_logs` 流水**，这是周报草稿的唯一数据来源，必须保证不丢。
4. **逾期为派生状态**（`due_date < 今天 且 status ∉ {done, cancelled}`），前端标红，**不入库**，避免定时刷库。

### FR-TASK-03 视图
- 列表视图（支持按项目、负责人、优先级、状态筛选与关键词检索）
- 看板视图（按状态分四列拖拽）
- 「我的任务」聚合视图（跨项目，按截止日排序）

### FR-TASK-04 任务可见范围
三个视图与任务详情、状态流水、项目看板、项目统计**共用同一套可见性口径**，避免"卡片上 42 个任务、看板里只有 2 条"的对不上账：

| 角色 | 可见任务 |
|---|---|
| 管理员 | 全部 |
| 组长 | 本部门成员负责的任务 + 归属本部门项目下的任务 |
| 普通成员 | **仅「负责人 = 自己」或「协作人包含自己」的任务** |

越权按 ID 直取详情返回 `403`。

## 5. 周报需求

### FR-REP-01 周期定义
- **自然周**：周一 00:00:00 ~ 周日 23:59:59。
- 周次标识统一采用 **`week_start`（周一日期）**，不使用 ISO 周字符串，避免跨年歧义。
- 时区：`Asia/Shanghai`，数据库 UTC 存储。

### FR-REP-02 自动生成草稿（核心算法）

点击「生成周报草稿」时执行，取以下**四类任务的并集**，按负责人 + 协作人分组（同一任务会出现在每个人的草稿里）：

| 序号 | 取数规则 | 归属段落 |
|---|---|---|
| 1 | 本周内（周一~周日）**流水变为 DONE** 的任务 | `done` 本周工作总结 |
| 2 | 当前状态为 `IN_PROGRESS`，或本周内有状态流水的未完成/进行中任务 | `progress` 本周工作进展（带当前进度%） |
| 3 | 本周内标记过 `BLOCKED` 的任务 | `risk` 需协调与帮助 |
| 4 | 未完成且截止日在**下周**的任务 ＋ 上周 `plan` 段中带 `task_id` 且仍未完成的顺延条目 | `plan` 下周工作计划 |

> 表内是**取数规则**的编号，不等于页面顺序。

**数据切片口径（关键）**：无论周五提交还是下周一早上补交，草稿内容一律锁定为「本自然周」内的任务流水与周终态，**不混入周一当天的变更**，确保跨周数据可比。

生成后草稿**完全可编辑**：可删条目、可改文字、可加自由条目。系统生成的条目标记 `source = auto`，人工补充的标记 `manual`。若该周已有草稿，重新生成采用**增量合并**：保留已手动编辑过的条目，仅追加本周新增内容，不覆盖人工修改。

### FR-REP-03 四段结构

**页面从上到下的填写顺序**（填写页、历史详情、团队视图、导出文件一律按此顺序）：

| 展示顺序 | 段落 | 必填 | 说明 |
|:--:|---|:--:|---|
| 1 | `progress` 本周工作进展 | 否 | 进行中事项及当前进度 |
| 2 | `done` 本周工作总结 | 否 | 本周期实际产出 |
| 3 | `plan` 下周工作计划 | 否 | 下一步安排 |
| 4 | `risk` 需协调与帮助 | 否 | 阻塞项，需管理者关注 |

**有效周报判定**：`done`（本周工作总结）或 `plan`（下周工作计划）至少一段非空且合计 ≥ **20 字**（缺省值，系统配置可调）。标记为无效后仍可提交，但在统计中单独列示，供组长关注。

### FR-REP-04 提交与锁定
- 提交时保存快照，**提交后锁定**。
- 已提交的周报需修改时走「修订」：生成 `weekly_report_revisions` 记录，`version + 1`，保留原快照，**状态（准时/迟到）不因修订而改变**。
- **保存草稿不受锁定限制**：已提交但未定版的周报仍可暂存改动（版本号 +1 并留痕，提交状态不变），
  避免用户改完内容点保存被拦截；**本周定版后一律禁止修改**（统计口径已冻结）。
- 一个人一周只能有一份周报（唯一约束 `user_id + week_start`）。

### FR-REP-05 代提交
- 组长/管理员可为成员代提交，状态标记 `by_proxy`，记录代提交人与事由。
- 该状态在统计中**独立成列**，不并入准时数。

## 6. 统计口径（本章为审计依据，变更需评审）

### 6.1 应提交人数

```
应提交人数 = 本部门在册在职成员数（周一 00:00 点名快照）
          − 本周期内有 approved 请假的成员
```

点名名册在**周一 00:00** 由定时任务生成并写入 `weekly_roll_calls`，之后即使有人离职/调岗，**本周分母不变**，保证统计口径稳定。

### 6.2 提交状态判定（五态互斥）

| 状态 | 判定条件 |
|---|---|
| `ONTIME` 准时 | `submitted_at ≤ 当周五 18:00` |
| `LATE` 迟到 | `周五 18:00 < submitted_at ≤ 下周一 09:30` |
| `MISSING` 未提交 | 下周一 09:30 定版时仍无 `submitted_at` |
| `MAKEUP` 补交 | 定版**之后**才提交 |
| `BY_PROXY` 代提交 | 由他人代提交（与上述时间条件无关，优先级最高） |

### 6.3 核心指标

```
准时率   = 准时数 / 应提交人数        ← 分母固定，不因补交改变
提交率   = (准时 + 迟到 + 补交 + 代交) / 应提交人数
未交率   = 未提交数 / 应提交人数
有效率   = 有效周报数 / 已提交数
```

> **不可洗白原则**：补交只增加补交列，绝不回填 `missing_count`。这是历史数据可追溯的前提。

### 6.4 定版机制
- **下周一 09:30** 定时任务执行定版：为全部部门生成 `weekly_stat_snapshots`，标记 `finalized = true`。
- 定版后该周历史数据冻结，看板读快照，不再实时聚合。
- 定版时同步把系统「当前默认周」切换到下一周。

### 6.5 统计看板维度
- 概览卡片：应提交 / 准时 / 迟到 / 补交 / 未交 / 有效数 + 准时率
- 部门横向对比（柱图）
- 近 12 周趋势曲线（折线：准时率、未交率）
- 个人历史明细（可查某人近 N 周记录）
- 连续未交人次 Top N
- 导出：**Excel + CSV**（两种均支持）

## 7. 通知与催办

### 7.1 提醒时刻表

| 时刻 | 类型 | 推送对象 | 渠道 |
|---|---|---|---|
| 周五 10:00 | 首次提醒 | 全部应提交成员 | 站内 + 邮件 |
| 周五 17:00 | 截止预警 | **仅未提交且草稿为空者** | 站内 + 邮件 |
| 周日 20:00 | 周末催办 | 未提交成员 | 站内 + 邮件 |
| 周一 08:30 | 最后通牒 | 未提交成员 **+ 抄送直属组长** | 站内 + 邮件 |
| 周一 09:30 | 定版结算 | 组长 / 管理员 | 站内 + 邮件（统计摘要） |

提醒时点可在「系统设置」中开关与时点调整（通过 `system_settings` 配置）。

### 7.2 渠道
- **站内消息**：`notifications` 表，前端铃铛角标。
- **邮件**：SMTP（SSL/TLS），账号走环境变量，禁止入库。未配置 SMTP 时自动降级为纯站内。
- **企业微信/钉钉**：`services/notifier.py` 预留适配器接口 (`Notifier` 抽象基类)，本期不实现。

## 8. 非功能性需求

| 类别 | 指标 |
|---|---|
| 并发规模 | 200 人团队、50 并发请求下响应时间 P95 < 800ms |
| 数据规模 | 单表周报 ≤ 200 人 × 52 周 × 5 年 ≈ 52,000 行，常规索引即可 |
| 可用性 | 单实例部署；备份通过数据库定时 dump |
| 浏览器兼容 | Chrome / Edge / Firefox 最新两个大版本 |
| 响应式 | ≥ 1280px 完整布局；768–1280px 自适应；移动端仅保证只读查看 |
| 日志 | 结构化日志落文件 `logs/app.log`，保留 30 天 |
| 审计 | 登录、改密、任务状态变更、周报提交/修订/定版、权限变更全部留痕 |

### 8.1 安全需求

| 项 | 要求 |
|---|---|
| 口令存储 | Argon2id（`time_cost=3`, `memory_cost=65536`, `parallelism=4`） |
| 口令策略 | ≥ 10 位，且大写/小写/数字/符号至少含三类 |
| 令牌 | JWT：Access 8 小时 + Refresh 7 天（HttpOnly Cookie 存 Refresh） |
| 首次登录 | 强制修改密码（`must_change_password`） |
| 初始管理员 | 命令行 `create-admin` 生成，**随机初始口令打印到控制台并写入日志**，严禁硬编码默认密码 |
| 传输 | 生产强制 HTTPS（Nginx 层终止 TLS） |
| 注入防护 | 全部 SQL 走 SQLAlchemy 参数化；禁止字符串拼接 |
| 越权防护 | 每一次资源访问做归属校验，组长仅能访问本部门数据 |
| 依赖合规 | 不使用已停止维护的库（如 passlib 1.7.4 的 bcrypt 组合），统一改用 argon2-cffi 官方实现 |

## 9. 数据字典摘要

详细表结构见 `docs/02-数据库设计说明书.md`，核心实体清单：

```
组织域   departments / users / department_members / leave_requests
项目域   projects / project_members / tasks / task_collaborators / task_status_logs
周报域   weekly_roll_calls / weekly_reports / weekly_report_items
         weekly_report_revisions / weekly_stat_snapshots
```

## 10. 验收标准

| # | 验收项 | 判定条件 |
|---|---|---|
| 1 | 任务状态流转留痕 | 任意状态变更后 `task_status_logs` 必有一条，且 `to_status` 正确 |
| 2 | 周报草稿自动生成 | 造 5 条不同状态的任务，生成草稿后四类段落命中率 100% |
| 3 | 数据切片不变性 | 同一份周报在周五与下周一生成的内容一致（不混入周一变更） |
| 4 | 准时判定 | 周五 17:59 提交 → 准时；18:01 → 迟到；周一 09:31 → 未提交定版 |
| 5 | 不可洗白 | 定版后补交，`missing_count` 不变，`makeup_count` +1 |
| 6 | 请假豁免 | 周三请假 approved，当周应提交人数 −1 |
| 7 | 权限隔离 | 普通成员调用他人周报接口返回 403 |
| 8 | 导出一致 | Excel 与 CSV 的数值与看板一致 |
